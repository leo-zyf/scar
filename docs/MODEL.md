# SCAR 程序模型

SCAR 用有类型的程序图表示源码行为，用执行记录补充调用和资源事实，再用独立的规划图表示可以改变的实现与时序。三者通过有版本的 ID 和工件引用关联。各层的输入与交接产物见 [编译流程](ARCHITECTURE.md)。

## 程序图

`ProgramGraph` 的主体是可递归展开的 Region、基本块和 Operation。Operation 包括算术、调用、分支、搬运、保存等操作。每条数据边以有序 Use 将 Value 接到消费端口，`f(x, x)` 保留两个端口。控制后继、调用进入与返回、状态访问、资源需求和顺序约束使用各自的类型。 [程序图类型](../scar/ir/program/model.py)

| 类型 | 含义 |
| --- | --- |
| Operation | 图上执行的操作。行为标签可以重叠，读写、效果和完成出口依附于操作。 |
| Value | 常量、块参数或操作结果。数据、引用、状态版本、局部绑定和协议值各有类型。 |
| StateLocation | 可读写状态的地址和范围。写入产生新状态版本。全覆盖仍保留必要的顺序约束。 |
| Region | 具有入口、块、参数和出口的展开边界。函数正文可由多个调用共享。循环用控制回边和携带参数表示，观测迭代各有执行坐标。 |
| Resource | 可分配、访问或消费的资源及约束。硬件拓扑表达 CPU、NUMA、内存、存储和已识别设备，以及连接、容量和可用性。 |

源码身份含编译单元、版本、来源范围和适配器。跨语言目标保留每个编译单元的语言、方言与选项。Python 静态分析可先保留可能的调用目标，运行证据再把实际调用接到相应的源码端口和展开上下文。在该输入下未观察到的候选继续保留条件。 [依赖类型](../scar/ir/program/dependencies.py) · [硬件类型](../scar/ir/program/target_hardware.py)

## 执行与数据身份

执行证据用独立坐标表示运行、进程、线程、区域激活、块访问、操作和操作数。它引用原程序图，同一源码操作可以有多个动态实例。设备提交、实际搬运、等待、完成以及内存位置各自存证。只有证据确认发生的传输才计为物理搬运。 [执行类型](../scar/ir/execution/model.py)

| 身份 | 判据 |
| --- | --- |
| 源码与执行 | CodeID 标识带版本的代码，InvocationID 标识一次动态调用。 |
| 对象与空间 | ObjectID 标识运行对象，StorageID 标识带生命周期的分配，视图用偏移、形状、步长和类型限定访问范围。 |
| 值与版本 | 图上 Value 和状态版本由定义及写入产生。跨对象或设备的等价须由来源、复制语义与适用条件证明。 |
| 物化 | 某个版本在具体设备、存储和表示上的副本，连同生产者与就绪状态。 |

早期 trace 的 `LogicalVersion` 是 storage/epoch 局部标识。当前通用构图保留源、版本和观测关系，跨任意复制及表示变化的统一等价证明仍未收口。对象 ID、地址、shape 或小样本只能用于定位或筛选。某个字段缺少依据时保留该字段的未知状态，其余已确定关系可继续使用。 [早期 trace 身份](../scar/ir/ids.py) · [物化](../scar/ir/entities.py)

## 化简、硬件与时间

可改写区域从操作、作用域和边界端口导出。化简须检查数据、控制、状态、异常、外部效果与逃逸等依赖。循环不变量外提还要证明值在外层可用、循环不会改变其读到的内容，并满足执行条件和效果约束。调用目标相同或引用相同只能帮助定位检查对象。 [区域边界查询](../scar/analysis/program_regions.py) · [循环投影](../scar/analysis/loop_graph_view.py)

`PlanningProblem` 引用原区域，登记实现选项、依赖、资源需求、搬运与时间约束。在支持的模型范围内，排程受可用核、队列、峰值容量、搬运和就绪关系约束，以完工时间为目标。时间代价记录其来源，区分模型、探针观测和缺失数据。静态字节数需要结合布局、资源和测量解释。精确求解结果只对已建模的约束和代价有效。 [规划类型](../scar/ir/implementation_plan.py)

规划与交付分开。规划发布选择及其证据引用，C++20 后端重读并核对计划、源版本和所需资源，再生成工程并验证输出。无可证明收益的计划可保留原执行。 [阶段交接类型](../scar/compiler/contracts.py)

## 持久化

记录用类型和 ID 引用连接。源码子图、调用关系和运行证据可按单元或角色分片，按需打开。原生入口另可交付一个有类型的 `program.json`。工件引用记录路径、schema、字节数与 SHA-256。压缩表额外验证解码后的长度、摘要和记录数。 [工件读写](../scar/artifacts.py)

退役查询入口与早期详细设计保存在 Git。用 `git show archive/scar-before-workspace-cleanup:docs/MODEL.md` 查阅相应版本。

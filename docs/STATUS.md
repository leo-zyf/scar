**Verified：本轮主链**

- 已有正式 F4 build 接入 29 个调用句柄、134 条边界依赖路由并独立读回；50 个字段前沿及 48 个未覆盖 entry 缺口仍保留，二者分母不同。本轮在原材料上补 scope 内部查询，不重签旧完整 build。
- 两个真实 Invocation 共用一个正文 lens，均能从参数经内部依赖到正常返回，再接回原 caller attempt；有界离线验证 23.335 秒。每 scope 的 1340 个句柄、1685 条内部条件边是查询结构，不是执行次数；效果和未知调用前沿仍保留，不证明内容保持或路径实际选择。
- 外部 Gray–Scott 从原 F4 自动接受 1 个区域，12 节点、189 条来源记录；其他 10 个函数明确拒绝。规则不按业务名称匹配。
- `observe-region-inputs` 只对匹配 CodeID 的函数开局部进入事件，两次元数据后关闭；一次真实完整短运行约 1.15 秒。百万步配置在约 1.17 秒取得两次元数据并停止本次子进程，明确标为执行前缀。未记录 Tensor/数组数值。
- 实际输入为 259²，沿原 slice 图得输出 257²、528392 bytes。先前误声明为输入 258² 的完整程序运行被 guard 全部回退，已保留为失败诊断并排除原生性能结论。
- 原语校准→静态工作量→成本预测→资源求解→C++ lowering 已接通。CPU 集合、增量预算、源码/资源收据、编译器完整 argv、runtime 指纹和实际 shape/layout 贯穿各层；更改求解成本而不更改校准证据会被拒绝。
- `choose-cpu` 在显式 CPU 池 0–7 内自动生成 1/2/4/8 核实现；复用已有 profile，只对缺失的 8 核上下文校准原语。预测完整调用成本依次为 423586/329454/246942/195926 ns，有限模型选择 8 核；`lower-cpu-choices` 独立重放全部域，只降低所选绑定。未编译多种目标实现并排名，原 Python NO_OP 路径仍合法。
- 这里的最优仅为 `OPTIMAL_WITHIN_FINITE_MODEL`。各原语拟合秩均 10/12，留出误差约 44.2%/11.9%/15.7%/27.0%；这是经验模型，不是任意程序的误差界或物理最优证明。缓存驻留与 NUMA 页位置未证明，逻辑字节数不等于 DRAM 流量。
- C++ 执行 timed 计划，逐调用检查输入/输出形状、连续布局、字节预算及 CPU 绑定/恢复；不按预测 tick 睡眠，不在每次调用重读源码或硬件文件。

# 三阶段与层间交接

三个阶段共同使用 `scar/contract.py`。各阶段可在独立进程运行。`scar/cli.py` 可以顺序编排三个入口。中端从前端图和图包内的材料读取。后端从中端的计划包读取。

| 层 | 输入 | 交给下一层的产物 |
| --- | --- | --- |
| F0 源码接入 | 入口和编译单元清单 | 源文件收据、每单元语言、方言与编译参数 |
| F1/F2 词法与语法 | 单元内容及其方言 | Python token 与语法材料，或原生前端的带位置编译记录 |
| F3 绑定 | 语法与声明 | 作用域、符号、调用位置和类型收据 |
| F4 语义图 | 控制、符号、值事实 | 可展开的区域、操作与边，循环保留进出端口及回边 |
| F5 证据与资源 | 图及系统信息 | 图的调用证据、平台资源和访问关系，以 `graph.json` 发布 |
| M1 合法性与化简 | 已锁定的图 | 有依据的改写记录，保留观察到的效果 |
| M2 资源与成本 | 合法结构、硬件图和已知成本 | 资源放置约束、已知或未知的成本和依赖 |
| M3 封存计划 | 合法结构和资源需求 | `plan.json` 及 `plan.payload/`，含可执行 IR、选定约束和验证输入 |
| B1 降级 | 封存计划及所需源码证据 | C++20 源码、头文件、CMake 与链接输入 |
| B2 构建和校验 | C++20 工程和独立验证用例 | 可执行文件、工件收据及验证日志 |

图中时间反映证据状态。尚无可比成本时，时间值保留为空。数组试验按目标 CPU 拓扑选组，并由 C++20 执行器分割工作和绑定线程。C/C++/Fortran 的适配归前端。当前原生控制图保留编译器 SSA 证据，封存的可执行叶子使用带 ABI 与链接配置的片段。原生语句到可执行 IR 的完整降级仍待实现。

后端包含三个文件。入口负责产物交接、校验及发布。 `lowering.py` 消费统一的 `ExecutableIR`，生成 C++20 项目输入。 `project.py` 负责 CMake、构建和链接核验。

CPU 验收在三个相互禁止导入的进程运行。后端启动前移走前端产物，并移动计划包。计划包内的文件使用相对路径和 SHA-256 收据。原图收据只用于追溯。系统工具链、链接库和工作负载声明的外部运行资源由目标平台提供。安装后的 wheel 运行同一验收，GitHub Actions 上传分发包与报告。

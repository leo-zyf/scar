# 三阶段与层间交接

三个阶段共同使用 `scar/contract.py`。各阶段可在独立进程运行。`scar/cli.py` 可以顺序编排三个入口。中端读取图包中的结构、资源和 `program`。前端的原始诊断记录放在 `evidence`。后端从中端的计划包读取。

| 层 | 输入 | 交给下一层的产物 |
| --- | --- | --- |
| F0 源码接入 | 入口和编译单元清单 | 源文件收据、每单元语言、方言与编译参数 |
| F1/F2 词法与语法 | 单元内容及其方言 | Python token 与语法材料，或原生前端的带位置编译记录 |
| F3 绑定 | 语法与声明 | 作用域、符号、调用位置和类型收据 |
| F4 语义图 | 控制、符号、值事实 | 可展开的区域、操作与边，循环保留进出端口及回边 |
| F5 证据与资源 | 类型化区域、可选观测用例和系统信息 | 图的调用证据、CPU 拓扑、缓存和内存域 |
| M1 合法性 | 已锁定的图和 ABI | 可改写区域、数据依赖与效果约束 |
| M2 图化简 | 类型化区域及其约束 | 改写后的逻辑 IR 和规则证明 |
| M3 封存计划 | 原版、改写版、运行守卫和验证输入 | `plan.json`、`plan.payload/` |
| B1 物理选择 | 逻辑计划、CPU 可用范围和探针数据 | `physical-plan.json`，含访存、算术和线程成本以及所选资源 |
| B2 降级 | 物理计划与可执行 IR | C++20 源码、头文件及构建配置 |
| B3 构建和校验 | 降级产物和独立验证用例 | CMake 工程、可执行文件、工件收据及验证日志 |

选择线程数、物理核和时间成本属于后端。闭合的逐元素区域使用同 NUMA 物理核分片，线程机制为 C++20 `std::jthread`。探针对比启动、带宽和运算吞吐，估算区间分离后才采用预计更快的线程组。原生动态长度区域可以按守卫执行已证明的循环融合。

源码语言适配归前端。在混编清单中，Python 单元可用 `abi.exports` 和 `abi.imports` 声明受限 FP64 标量接口。前端把调用绑定到匹配的原生声明和符号。可选的 Python `observe` 用已声明参数运行一次入口，并保留带调用位点和数组元数据的有界报告。原生区间通过 SSA 和源锚点封存。Fortran `BIND(C)` 发布有序参数、传参方式、布局、链接符号和声明收据。一维计数循环以该收据绑定到导出符号，中端核验后应用共享融合规则。后端统一生成 C++20 包装函数、f2c 支持头和所需的 GNU CFI 兼容实现。循环守卫由后端按生成后的函数体位置插入。

C 输入原样封存，兼容声明记录原始坐标上的链接范围、指针转换和旧式参数。中端的循环证明沿用同一坐标。后端在一次源码组装中合入兼容生成和循环守卫。

CPU 验收在三个相互禁止导入的进程运行。中端启动前移动图包，原生用例同时移走源文件，并检查移除诊断记录后仍能化简。后端启动前移走前端产物，并移动计划包。图包和计划包内供下一阶段使用的文件通过相对路径和 SHA-256 收据引用。原图收据只用于追溯。系统工具链、链接库和工作负载声明的外部运行资源由目标平台提供。安装后的 wheel 运行同一验收，GitHub Actions 上传分发包与报告。

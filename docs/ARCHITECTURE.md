# 阶段与层间合同

三个阶段的公开入口是 `scar build`、`scar plan`、`scar compile`。阶段入口只负责按序调用本阶段的层。各处理层通过明确产物交接，公共格式、摘要、路径校验和操作遍历位于 `scar/contract.py`。`scar/host.py` 只读取执行主机的 CPU 亲和性和可见带宽配额，供各阶段独立消费，不导入任何阶段实现。

多镜像交付时，B1 从已具备原生实现的子程序中排除传递依赖未就绪启动目标的程序。其余镜像直接引用原调度记录。B2a 核验实际启动目标和 IR 摘要，B2b 与 B3 使用同一条打印和构建路径。完整应用的状态由入口决定；调用者可从 `result.json` 的 `component_delivery.executables` 取得已生成的组件及摘要。

M2 在原导入位置保存已访问的外部加载操作和实际返回对象。即使没有消费者，审计、错误或文件效果仍可见。有消费者时，状态检查可沿操作数边记录属性链、调用目标和实参位置。B1 据源导入清单核验目标效果；历史 IR 中被省略的加载也参与交付判断。已证明不可达的导入不触发该判断。

## 前端

| 层 | 输入 | 处理与输出 | 实现 |
| --- | --- | --- | --- |
| F0 输入 | 入口、编译清单或锁定的构建记录 | `SourceRequest`；可选构建发现子流水线先恢复单元任务，随后校验源码摘要和输入缓冲 | `input.py` |
| F1 事实捕获 | 单元任务 | `ParsedUnit`，持有已捕获的语法、作用域、类型、源码缓冲和实际 ABI。Clang 捕获的实际项目头文件也参与摘要 | `capture.py`、`builds/facts.py`、`languages/*/facts.py` |
| F2 正规化 | `ParsedUnit` | `NeutralUnit`，含类型化操作、过程、记录、全局状态、外部接口、转换依据和定位缺口 | `builds/normalize.py`、`languages/*/normalize.py` 及同层操作模块 |
| F3 构图 | `NeutralUnit` | 操作记录表、端口、控制区域、符号调用与状态域 | `graph.py` |
| F4 状态分析 | F3 图、访问表 | may-def epoch、合流、循环携带关系；未闭合区域局部摘要及覆盖范围 | `state_flow.py` |
| F5 封存 | 各 worker 从 F4 单元图提取的操作端口、构建证据、平台事实 | `graph.json` 与 `units/` 内容寻址成员，含 CPU 池/逻辑核/物理核/NUMA/DRAM/存储/可见设备拓扑 | `hardware.py`、`artifacts/graph.py`、`pipeline.py` |

前端 `__init__.py` 只导出入口；`pipeline.py` 依次编排 F0–F5。`capture.py` 只协调输入发现和编译配置去重，产品为 `CapturedProject`，不构建操作图。脚本镜像可与单一 `build_trace` 同时声明；生成的 `build.bindings` 以构建产物 ID、镜像 ID、单元索引及记录摘要连接两类子图。该连接只证明捕获的编译／链接来源，历史输入版本、构建输出流及配方效果仍保留未证明字段，不能据此删除运行时 Make。F3 的 `unit_graph` 独立接收中立单元，不修改 F2 输入，也不调用 F4。

按语言分包的 C/C++、Fortran、Python 适配器都公开 `parse_unit` 和 `normalize_unit`。F1 产品允许在同一工作进程内保存编译器 AST 及已捕获源码的所有者，F2 通过它读取事实。F2 接口测试会移走源码，并禁止打开文件、启动编译器和重新解析。它输出的中立记录可以序列化。F3 和 F4 分别接受普通数据，构图函数自身不会启动状态分析。

构建发现同时保留文件的规范路径、原始编译操作数和编译工作目录。F1 用规范路径锁定源码字节，用原始操作数解析 C/C++ 的 `__FILE__` 和相对头文件。GNU Fortran 的 I/O 源位置取自同一次编译的语义输出。这三个量在图中各有用途，同一个文件经不同拼写传入时可能产生不同的可观察结果。

Python F1 对全部绝对导入捕获根模块、限定模块及父级的标准查找结果，不以已实现的库名决定是否收集来源。外部包按实际选中的文件核对发行包成员及可用的安装摘要，明确区分命名空间、缺失、未登记和摘要不符；文件归属不代表实现或副作用合同。发行名映射按需查询一次，只索引候选包的成员。捕获不执行目标包或父包初始化器。项目源码仍进入项目子图，F2 把已捕获身份交给 F3，不再次查询环境。

F1 的 `imports.py` 单独管理上述身份和按需导出追踪；`facts.py` 保留程序语法、作用域及项目发现。导出追踪沿显式导入、别名及可解析的星导出记录定义候选、源码摘要、定义时序、条件与执行语句位置。未知命名空间写入保留未解析路径；候选来源不等于运行时绑定。F2 只传递这些已捕获数据，不重新读取或执行外部包。公共来源策略位于 `source_contracts.py`，不再混入 `contract.py` 的格式与收据原语。

Python 数值数组可以显式声明有界运行观测，作为 F1 输入事实。模块初始化、闭包和本地 import 可以静态建图；尚未闭合的运行时类、接收者、库操作及效果保留为字段级问题。Python 官方驱动的结构图覆盖情况与可执行支持范围分别报告。

Python 入口可在 manifest 的 `entry_environment` 声明 standalone_script、embedded 或 unspecified；多镜像逐镜像声明。F1 在源码发现前只记录一次分析进程的解释器、启动标志、导入器及缓存快照，F5 在 `graph.source_facts.python_entry_environment` 封存。该快照明确不是应用初始缓存，部署等价性与 audit hook 仍未证明。M1 只读图包，为入口实例和函数作用域绑定证据 ID；M2 导入账本保留相同证据，B1 只作来源审计，不能据此消除未知初始化效果。

多镜像清单中的 `source` 脚本由 F0 锁定入口字节，F1 自动发现本地模块，F5 才封存展开后的单元索引。源码归属根与脚本搜索起点分别记录；物理文件的语法可共享，导入绑定依各脚本上下文确定，不能仅按文件路径合并不同程序。

Python 函数体先经过同一协议正规化，再依据显式标量或数组接口判定数值资格。资格判定消费操作记录，不再次遍历函数体 AST。标量调用按 Python 求值顺序显式绑定结果；整数字面量子表达式在转换浮点前保留精确值。可变模块/闭包绑定和循环回边上的候选值带状态守卫，不能作为无条件常量。类体和方法保留各自作用域，运行时 MRO、元类等边界明确标注。

语言覆盖必须分别记账：解析器识别、F2 明确表示、M2 执行合同、B1 原生供应和 B2 目标实现不是同一个状态。每条规则应声明语言版本／方言、输入字段与作用域、求值顺序、类型与状态效果、输出端口及未闭合条件。未知声明不能静默消失；透明包装也需要具体依据。审计清单保存在 `artifacts/current/language-coverage/index.json`，详细记录对应捕获时的源码摘要，不能将处理分支数量当作整语言支持率。

下一轮按整族推进：先补所有源构造的覆盖记账与静默遗漏，再处理类型／存储／绑定与转换、表达式／结构控制、调用／对象生命周期、I/O／异常／并发，最后分别资格化外部库。每族沿 F2 → M1/M2 → M4 → B1/B2 交接，消费方只读取上层产物；禁止为某个测试程序追加特例。当前 Python 仍缺模式、异常组、完整闭包及挂起恢复；C/C++ 仍缺若干存储、旧式 ABI、对象及扩展合同；Fortran 仍缺部分源单元、描述符、READ、过程与并发族。语法盘点完成不等于这些功能已经实现。

有界的 `source_coverage` v1 随 F2 单元进入 F3 封存图和 F5 索引。记录包含语言、明确的覆盖范围、构造类别、作用域、位置及 modeled／transparent／incomplete 处置；未闭合项必须有诊断。M1 核对索引与封存成员，并从成员恢复被索引遗漏的诊断。当前 Fortran 范围是程序单元与规范区，C/C++ 范围是项目查找／属性元数据和局部语义诊断，不能据局部 complete 宣称整个语言完备。未支持的 Submodule、模块持久状态及可能影响链接或初始化的属性不再静默消失；Fortran 已证明的模块 PARAMETER 可传给未被局部声明遮蔽的子程序。

M2 的 `normalization/obligations.py` 按有限规则批量处理源诊断，不逐条写特例。词法归属、源构造、导入目标、调用绑定、规范函数体、库接口、类创建及进程参数分别归属明确层次。每个位置保留 `OPEN`、`M2_RESOLVED`、`PROVEN_INACTIVE` 或 `DEFERRED_TO_B1`：闭合函数与成功规范化的确切源站点可证明已完成的 M2 工作；类创建需要精确创建证明；未选路径需要控制证明。部分前缀、递归临时签名和未编译函数不算已完成。M4 将逐位置账本封存为独立成员，计划只列规则分组和引用，B1 接力复制审计成员。诊断原文中的源码行不进入此产物；M2 完成也不替代原生接口及外部效果资格。

Python F2 的 `python_select` 明确表示条件求值后只取一臂；`sequence_comprehension` 与字典推导式共享词法作用域、嵌套生成器和过滤结构。未知协议保留带命名字段、标量、上下文与跨度的纯语法证据，不把所有子表达式伪造成顺序执行。M2 对已闭合的选择生成互斥区域及值合流，对同步列表推导式生成真实序列构造／追加与结构循环；外层迭代器先于结果容器建立，循环回边上的赋值及数组别名事实先失效。条件确定时，未选分支沿已有证明账本排除。列表使用已有 C++20 序列供应，不另造后端。任意异步迭代、闭包捕获、自定义迭代器、异构动态合流及可变列表的完整显示协议仍未闭合。

F2 文件与流投影集中于 `languages/python/io.py`，仅引用已有操作数和绑定证据；F5 `artifacts/graph.py` 以纯数据连接这些源站点、解析器拥有的文件缓冲、构建输入和镜像。M1 校验独立图成员，再交给中端；不回读源码。解析器本次读取与原始编译器历史读取分开建模。

可识别的进程协议保留启动、句柄、标准流和等待端口。函数分片及摘要中的 `process_operations` 索引这些静态操作；它不代表实际已启动的进程。句柄实例、流和方法绑定仍受原库/对象守卫约束。

已核验的外部 Python `.py` 也沿同一 `ParsedUnit → NeutralUnit → unit_graph` 通路建图。逻辑 `source_key` 与物理 `origin` 分离，F5 据封存来源连接真实文件；源码、AST 和作用域按内容快照共享。每个单元只携带可见模块目录，普通导入绑定不自动激活函数体。公共源接口登记仅确定展开边界，执行语义仍由消费者单独资格化。

F1 分别记录 source、bytecode、extension、frozen 和 builtin 加载来源，只有已核验的源码加载器才提供可展开的 `.py` 成员。项目／发行包直接请求的未登记标准库源码沿同一通路展开；更深的标准库依赖明确记录为展开前沿，不执行初始化器来补事实。父包初始化顺序单独保留。已登记的公共模块接口只是当前展开边界，不能据此认定其整个命名空间已支持或初始化无效果。

模块来源与 `graph_backed` 分别记录。属性读取先查当前命名空间，缺失时才可能沿条件边调用真实 `__getattr__`；已绑定属性可机械排除对应候选边。包的 `fromlist` 检查与最终属性读取是不同动作，涉及 AttributeError、子模块加载及缓存合流的未闭合路径保持明确义务。

Fortran F1 封存所选 GNU 编译器、源码摘要与源上下文浮点选项，并从真实 f951 参数锁定自动预包含文件；原本启用 CPP 的源文件可从同一次语义命令取得依赖清单。来源证据与内容身份分别合并，未选中的 include 不进入版本链。F2 保留表达式类型、intrinsic 参数及 KIND 依据，并仅将源编译配置明确授予的 errno／舍入权限投影为函数合同。M1、M2、M4 分别核验来源摘要和权限上界；B1 用编译探针资格化目标支持，B2 以类型化函数属性消费决定。全局严格浮点选项和其他函数不变；权限传递不等于数学调用已向量化或已经加速。未核验的 include 内容和运行时浮点环境仍标为未决。

依赖采集选项只附加到真实源文件的语义捕获；对已预处理文本的兼容性检查独立关闭 CPP，不继承依赖采集参数。M1 在读取封存图时校验数值合同的源码摘要、编译选项、函数归属与数学声明头证据，不重新读取原文件。

M2 的模块注册表证据独立于代码编译缓存。`importlib` 初始化形成显式 `module_namespace_initialize` 和 `module_registry` 供应义务；未证明的冷加载、状态失效或未提供原生供应时，不能交付可执行包。后端目标树可用受限 `asm_label` 表达外部 C 函数的库链接名，尚未授权生产数学调用自动使用向量变体。

跨外部导入继续使用已初始化模块时，注册表身份与命名空间读取分别记录消费者及源站点。条件化分析必须保留正常继续所需的状态合同；未实现的源等价继续路径阻止后端交付，不能由断言、空操作或 Python 回退替代。B1 按实际调度操作记录数学接口的源合同、类型、头文件依据、目标资格和未证义务；保留原操作与批准向量化是不同结果。

源导入出现记录独立保存为 `source_imports`：初始化生产者、各名称绑定和后续只读状态检查分别关联，不用检查操作再次执行初始化。M4 将账本封存为内容寻址成员，未闭合程序的计划与执行包也保留引用。B1 的 `source_import_effects` 分开报告源码建模与目标接口供应；能生成已有接口的 C++ 不证明冷初始化、钩子和失败效果全部等价，尚未覆盖的部分继续明确标为未证。

导入效果摘要区分直接注册表键、条件 fromlist 键和命名空间写入，其他注册表写入、钩子及外部效果未证明时仍为 `UNKNOWN`。M2 的每次可能写入都推进状态 epoch，包括先前未知或缺失的条目。合流只保留每条入边共同支持的身份及待检查条件。已有显式结果捕获的未知动作，可在原动作前后记录状态、在消费者处增加条件检查；动作只执行一次，失败边必须携带原结果继续源等价执行。它仅形成条件化 IR，尚未提供的原生状态读取或失败续体仍由 B1 拒绝，不能以断言、重执行或 Python 回退替代。

精确内建文本及原始参数通过同一描述符规则处理 31 个方法；涉及非 ASCII Unicode 的结果需要源解释器 Unicode 版本匹配。文本产生的列表／元组保持新建身份。序列域最多保存 64 个由初始化表达式证明的成员描述，包括已知类型、可证明的值和子序列身份。成员数与类型已知时，数值仍可未知。模块公开列表保留运行时身份和实际索引读取。M2 按调用边将形参、视图及本地赋值追溯到实参，写入使相应存储事实失效。无法界定回调写入时，所有可能暴露的数组及序列事实失效。

Fortran 非整数幂的操作数转换在 F2 显式表示，同时保留转换前后的类型。GNU 目标 ABI 来自同源编译选项查询，可区分 x86_64、x32 和 i386 的声明条件；判定成立不代表已经向量化或安装了对应数学库。B2a 验证 B1 数学决定关联的函数成员、操作路径和实际降级访问，拒绝尚未实现的向量选择；目标与工程清单保留消费摘要。

模块初始化器中的字符串字面量直接赋值可记录同一代码对象的常量槽、名称槽，以及装载和写入指令的位置。M2 对照图中的右值、目标和作用域生成有副作用的命名空间写入。实际执行要求当前帧与该代码对象及操作数匹配，保持原常量对象身份、写入失败和被替换对象的释放顺序。M4 的字节数与存储来源推导在开放写入处失效，包括循环回边和容器构造。B1 必须为命名空间操作与失配后的执行路径提供原生实现。

F1 对同一代码对象只反汇编一次。F2 将具有唯一位置的名称读取连到源码操作数。M1 核对源码、模块作用域和编译器，恢复图端口。M2 的 `namespace_operations.py` 用这些端口表示开放命名空间上的读取、调用、富比较与真值测试。被调对象在求值实参期间保持存活，短路分支按求值结果选择。`import_state.py` 负责导入状态的版本与合流。诊断位置前已还原的表达式随分析前缀封存，B1 单独检查原生实现。

简单绝对导入沿同一通路保留请求参数、当前导入函数、返回对象和目标绑定的关系。F1 容许解释器从常量池或立即数装载 level。M1 复核四条指令的顺序和实际目标槽。M2 只在经过导入的分支上发布绑定，导入抛错时跳过写入，分支合流时只保留各路径共有的发布证据。后续读取仍需访问当时的绑定。

F1 的导出候选可沿赋值与重导出到达有准确源类型和位置的字面量，发行包版本不替代源码属性值。M2 在原导入／读取位置保留初始化与命名空间查找，只有检查实际类型和值后的正常边才取得精确事实；取值投影与检查共用一次实际查找。检查失败要求源等价继续路径，不能用异常、断言或 Python 回退代替。没有原生命名空间及续体供应时，B1 仍拒绝交付；候选不被误报为可直接硬编码。

## 中端

| 层 | 输入 | 处理与输出 | 实现 |
| --- | --- | --- | --- |
| M1 绑定 | 完整图包 | `BoundProgram`，连接入口、符号、记录与全局存储，闭合普通调用、回调和隐含对象生命周期，保留声明变体及状态证据 | `binding.py` |
| M2 规范化 | `BoundProgram` | `CanonicalProgram`，检查 ABI，明确引用/指针和旧方言转换，生成标量归属与逃逸合同，记录原版缺陷与处理证明 | `normalization/program.py` 及同层领域模块 |
| M3 化简 | `CanonicalProgram` | 等价改写后的操作及证明，包括有界索引、整数常量、重复域和合法融合选择 | `rewrites.py` |
| M4 执行封存 | 逻辑操作、约束与改写记录 | 迭代布局、生存期、局部数值缓冲区的允许访问方式及复制/物化关系，输出 `exec-ir.json`、`functions/`、`resources/` | `execution.py`、`resource_flow.py` |

M2 的实现统一归入 `normalization/` 包：`program.py` 负责本层协调和 ABI，`protocols.py` 负责源协议、名称与控制，数组、标量、文本、对象、异常、图形、主机、进程和 MPI 各由同层领域模块处理，`values.py` 提供本层值记录。公开入口仍为 `normalization.normalize`；旧平铺模块删除，不保留转发垫片。

中端整程序交接使用 `contracts.py` 的 `scar.middle-program` v1 合同，标明 M1–M4 与 complete/partial。M2、M3 的 `rewrite` 和 M4 的 `prepare` 只接受上一层产物；函数级改写辅助器不等于整程序入口。M2 先闭合接口、调用参数、MPI 效果和状态合同，再派生文件/缓冲关系。派生结果携带 `basis`，区分完整 canonical、协议前缀和接口前缀；M3 后仍是明确来自 M2 的证据，不冒充重新计算后的图。各层不得修改输入：M2/M4 保留独立工作副本，M3 重建函数体并独立复制其所有权注解。阶段校验只核对交接格式和次序，不替代合法性证明；尚未拆开的共享状态和大型分析器仍是结构债务。

M2 的 `import_state.py` 独立拥有注册表、名称版本、失效及延迟守卫窗口，提供快照、合流和异常／清理路径投影；它不接收 Project/Frame 或调用编译器。协议编译器借用守卫记录身份，独立复制状态容器。命名空间守卫的 `binding_reads` 保存每个实际读取的名称、分析 epoch、消费者和源站点；epoch 不表示内容版本。可达值状态尚未精确投影时仍标为 unproven，保留原强守卫。B1 缺口报告按实际执行操作给出有界、带省略计数的读取需求，不把历史证据副本当可执行节点。

固定异构容器由同层 `products.py` 管理构造、投影和跨激活事实；公共 `product_ref` 格式在 `contract.py` 校验。F1 捕获元组构造及常量池身份，F2 仅转交；M2 生成通用容器操作，B2a 的 `objects.py` 消费该合同生成目标树，不读取 Python 编译事实或源码。后端常量池使用按需初始化、跨翻译单元共享的访问器。

`artifacts.py` 从规范操作推导流写入、文件版本模板及有限的跨函数常量上下文；`buffers.py` 处理 C 字节区域的版本、合流、循环和命令依赖。二者只扩充公共 artifact graph，不执行源程序、不调用其他阶段，也不批准后端进程边界。源码中的启动调用与单独捕获的构建记录尚不能仅凭相同路径或命令目标合并为同一次执行。

文件分析沿有界的正常调用路径维护符号 cwd 和当前文件版本：成功关闭写流后发布版本，已知普通文件复制产生独立位置和版本、共享字节值，读取接到当前版本。已闭合标量参数的文件调用继承调用者状态，返回正常状态转移；每个根激活及静态调用点最多实例化一次，重复、递归及未证明的别名进入显式边界。独立函数模板不共享状态。函数体先各扫描一次，FILE/OPAQUE 效果经逆调用边单调传播；无文件效果或只有不透明效果的调用不递归展开文件分析。`file_state.py` 单独维护目录身份及父关系，支持已证明目录的复制目标；现存目录的 `..` 不做字符串消除。分支隔离快照，以 phi 连接正常出口的文件版本和目录身份；循环只作出口摘要，不展开迭代。跨调用流句柄及部分清理区域仍是边界。边保留正常完成、排他写入、别名及并发义务，条件化关系不授权删除文件操作。

M4 的 `workflow.py` 只消费各镜像已封存的执行 IR 与审计图，连接声明镜像的入口状态及直接子进程等待。它不读取源码、不调用 M2，也不按相同路径猜测消费版本。工作流以内容收据进入总包和 B1 调度包；引用按镜像审计图身份解析，不留下原包路径。

文件分析按入口捕获的身份处理正常 `resource_scope` 清理，变量重绑和分支快照不改变待关闭对象；完成后继续后续等待。非正常退出和身份未闭合的数组输入流仍保留边界，不将清理条件当作已执行事实。

M1 至 M4 的处理模块只依赖公共格式层。它们互相不调用处理函数。`middle/__init__.py` 按顺序接通产物并写 `plan.json` 审计。M2 不能依据函数名称修补程序，M3 依据数据、类型、边界和效果证明规则。M4 给出合法选择及守卫，设备、线程和物理代价由后端决定。模块注册表、命名空间失效和绑定版本随控制路径快照／合流；正常初始化与异常前缀分开，重新赋值形成新绑定版本。状态比较失败仍须等价续体供应，不能把分析假设当运行事实。

M4 的 `resource_flow.py` 是本层纯数据域组件，消费已有规范操作，连接复制端口、物化、源硬件域和就绪关系，不重跑语言前端或 M2。文件路径未决时仍保留复制操作及请求端口，不把它视作已知 NVMe 传输；view/reshape 保留可证的存储来源。图按循环/分支模板记录，独立成员可搬移，B1 经收据读取，不回读上游源码。尚未闭合的程序只输出标明范围的分析图。

M1 的 `activation_graph` 保留入口／初始化根及逐站点调用边，站点是 F3 的 `graph.id/port`；无法归因的调用摘要、外部函数引用保持硬边。M2 仅裁掉已证明未取的分支、短路尾部、空循环及无正常后继的操作站点。实际解析调用仍加入可达性图。只有从原可达集转为不可达集的 Python 过程体才可省略，不能把“尚未编译”当作不可达。证明随 `inactive_activation_edges` 交付；定义的默认值、注解、装饰器和类体仍属于各自实际执行的位置。

Python 结构图的可执行资格属于 M2。M1 保留源协议函数体、作用域和未闭合合同，不能把它们误报为缺失定义。M2 的同层辅助 `protocols.py` 按模块初始化顺序、实际名称绑定和调用实参类型生成中立操作；重复导入只执行一次初始化，可变模块标量使用真实全局槽。开放协议先阻止原生 ABI 检查，避免把 Python 关键字调用误报为 C 参数数量错误。`protocol_analysis` 分别记录已闭合签名和首个缺口；M4 禁止把剩余源协议封成 `READY`。生成器、协程、默认值与注解的执行时机保留在 F2，未实现的协议不会被直接删除。

`expressions.py` 在同一 M2 层集中绑定二元／原地运算、比较链和 `and/or`。比较中间值只捕获一次，尾部降为守卫内的 `if` 区域；条件上下文只合并真假，值上下文返回选中的原值且要求可表达的源类型。分支间状态按现有合同合流，别名写入的失效不会因名称恢复而撤销。`numpy_bool` 与 Python `bool` 是不同逻辑类型，尽管两者物理表示均为布尔值；源 NumPy 版本决定其显示规则，不用存储类型替代源类型。

导入依次检查请求与控制域、准确模块的来源、初始化及导出合同。根库身份不能替代子模块身份，属性缺失时的子模块候选不能被无条件选择。已核实来源但没有执行合同的包报告 `import_semantics`，查找不到报告 `import_missing`，来源证据不全、冲突和命名空间分别定位；这些情况均保留导入操作及效果，不生成空实现。只有本层已实现的标准库或数组合同可以进入执行 IR。

M2 的 `values.py` 定义值、类型键和保守事实；`scalars.py` 处理 Python 标量范围及实数幂；`arrays.py` 处理 NumPy 标量、序列、数组和广播，不导入 NumPy。`text.py` 统一容器表示、字段转换和格式规格；`host_protocols.py` 负责已核验标准库的参数绑定及主机效果合同。`exceptions.py` 负责异常前缀、处理器绑定、正常／提前出口和资源清理；`protocols.py` 连接名称、调用和控制流。这些是 M2 的同层职责，不是跨阶段捷径。F1 捕获发行包身份与实际导入来源，F2 将其写入导入图，M2 再判断受支持接口。内建和冻结模块先于路径查找，同名本地路径模块按项目源码处理。文本编码及标准流错误策略来自 F1，不能在后端猜测。

`mappings.py` 处理 `builtin-scalar-map-v1`：文本键及带独立标签的 None／bool／i64／f64／text／嵌套映射，保持插入顺序、共享身份、活跃 items 迭代与修改检查。F1 捕获字典构造的实际求值批次，F2 保留推导式作用域及生成器／过滤条件，M2 降为有序构造与循环；不缓存可变内容或迭代长度。递归只接受已证明向嵌套数据下降且调用效果闭合的受限情形；任意递归、自定义键和循环引用仍未支持。B1 独立核验类型、操作集和私有构造证明，B2 消费统一操作并使用固定 `mapping.hpp`，不读取 Python。

函数创建与函数调用分开。M1 传递被定义函数的签名与默认参数来源描述，即使其函数体没有调用边；M2 在定义点求值默认参数一次，以持久共享值交给后续调用。函数体是否可执行另行判定，不能为了定义默认参数而伪造空函数体。装饰器、注解、重复动态定义和传入闭包的完整创建协议仍须独立闭合。

标准实数数学同属标量合同：核实导入后，24 个单输入函数及三个浮点分类接口降为中立 `intrinsic`；带底数 `log` 分为有序对数、零分母错误和除法。定义域与溢出按 [CPython 标量数学规则](https://github.com/python/cpython/blob/3.12/Modules/mathmodule.c) 写为显式异常区域，已证明的输入域可消去错误边。错误表示消费捕获的源解释器配置，分别保留 3.10–3.13 与 [3.14 的参数化诊断](https://github.com/python/cpython/blob/v3.14.7/Modules/mathmodule.c)，不能用运行 SCAR 的解释器版本替代。B2 仅将计算和分类原语交给 C++ 标准库，保留单次求值；不实现数学内核。自定义转换、多值结果及尚未登记的数学接口仍须独立合同。

内建真除法的分母可能为零时，M2 先保存操作数，再生成异常分支。由 CPython 来源合同确定的 i64 到 binary64 转换在 IR 中注明最近偶数舍入，B2 对完整 i64 范围实现该合同。反方向的浮点到 Python 整数转换，超出 i64 的有限结果仍需要无界整数表示。

普通 Python 的 `range` 和 `while` 保留循环，实参和范围端点在原求值位置捕获。循环内被写入的值先放宽事实，再根据范围和条件推导；循环正常退出、`break`、`continue` 与 `else` 分别合流，零次迭代不能凭空创建绑定。目前 `range` 步长需要证明为非零常量，自定义迭代器尚未闭合。

可变同类型序列使用 `sequence_ref(element)`，分配在源构造位置保留。M2 的私有元素约束允许空序列经后续追加、函数参数和返回值解出类型；未解或冲突时给出定位缺口，公开函数、全局及前缀产物不能含私有类型变量。仅对私有且所有用途已证明的列表保留编译期描述。公开列表使用真实共享引用，已证明标签的异构内建标量可从当前成员投影。序列物化为独立数组时，M4 记录逐元素转换的来源边。B1 核验元素、秩和所有权，B2 生成按索引读取、转换并新建存储的 C++20。用途依赖穿过赋值、已绑定项目模块槽和索引投影；写入、身份观察及逃逸沿依赖边反向传播，不能因局部读取为常量就丢掉其他消费者。迭代器捕获容器引用，每步读取当前长度，追加可见，变量重绑定不改变已建立的迭代器。B2 独立消费构造、追加、长度、索引、身份和排序副本六种操作；文本排序另需无损码点表示资格，未知文本拼接不能自动取得该资格。

标准库来源还包含所请求 Python 模块的直接绝对导入记录，不递归扫描整个标准库，也不据查找结果声称初始化已经执行。当前 `glob` 逻辑合同针对已审计的 CPython 3.12.3 POSIX 来源，分别保留模块初始化和非递归字符串模式的目录枚举，输出新的文本序列；任意路径分量都可以有通配符。缺少原生初始化／枚举实现时，B1 仍拒绝交付，不能用空导入或排序后的目录结果替代源行为。

`processes.py` 是 M2 的进程领域模块。它消费 M1 从完整图取得的显式镜像目录，将已声明应用命名空间中的直接目标写为 `process_spawn(image_id, argv, routes)`；不解析 Makefile、不执行构建、不把任意同名文件当作已编译子程序。管道读取沿共享文本流处理，逐行迭代降为有 EOF 条件的循环，`wait` 保留 ORDER 效果。管道路由属于编译期不变合同，来源类型顺序换绑只在物理表示相同的槽内复用，仍保留当前逻辑类型。

合法进程协议与执行目标绑定分别表示。目标未闭合时，M2 生成 `process_request`：保留原命令表达式、管道、编码、cwd、外部效果及目标义务，继续分析后续等待、状态和控制；不拆解任意 shell。请求 ID 来自静态调用站点，与捕获 PID 无关。`CalledProcessError` 的已闭合字段写为独立 `process_error_make`，不冒充普通异常或删除错误分支。M2 的逻辑资格不授权执行这些请求；B1 必须拒绝未绑定目标及未实现的异常接口。

源程序显式调用的标准 `system` 与编译器自行启动原应用兜底分别处理。M2 仅给实际 libc 声明、参数绑定及命令请求一致的直接调用附运行时边界，保留 CTRL／IO／ORDER／STATE／OPAQUE 屏障。B1 用不调用 `system` 的原生探针核验目标声明与 libc，记录 shell 的存在或缺失；B2 核对逐站点资格及调用摘要后按原指针调用 `::system`。API 已绑定不证明 shell 后代、展开参数、工具或成本已知，这些范围在物理计划和调度 IR 中保持开放；不将 `"mkdir %s"` 等动态命令擅自改为文件系统算子。

B1 核对部署 SDK 的版本、摘要和可用文件，B2 消费该物理选择并调用 xtensor。固定运行时支持保存在独立的 `runtime.hpp`、`array.hpp`、`format.hpp`、`text.hpp`、`host.hpp`、`exceptions.hpp`，不是 Python 内嵌的应用代码模板。B2a 把实际用到的 SDK 字节、依赖闭包及摘要封入目标包，B2b 只读取该包。数组格式化使用共享视图和标准数值转文本接口；文件流的别名关闭、UTF-8 字符计数、通用换行和复制元数据由原生支持层实现。SDK 供应与 CI 位于工具层，编译阶段自身不下载或安装依赖。

MPI 的 F1 证据是 Clang 已加载的外部头内容摘要，经 F5 和 M1 交给 `resource_model.software_headers`，后端不回读原头。M2 同层 `normalization/mpi.py` 仅识别真实 MPI provider，保存阻塞／非阻塞／持久请求与同步时点，不能按名字改写用户函数，也不从历史 evidence 引入 SDK 需求。B1 `planning/mpi/sdk.py` 消费这些 IR 和本机 SDK，以固定 `planning/mpi/probe.cpp` 核对 ABI、版本、实际头闭包及直接链接输入；探针只查询库信息，不初始化 MPI。B2 封存 SDK 收据并生成项目检查，B3 通过 CMake 验证当前 SDK 字节。中端不选 rank，后端当前明确将 rank 选择与通信成本标记为 `unmodeled`；MPI 库调用通路不等于自动 MPI 并行化或全局通信调度。

F1 将源解释器版本及 Unicode 不可打印区间封存为共享、内容寻址的静态事实，作用域只保存其 ID。M1 校验身份并去重，M2 把格式串解析成显式规格，保留源版本的值、嵌套规格、转换和格式化次序。闭合函数所有返回路径一致的标量事实可以向调用方传播，但实际调用及副作用仍保留。B2a 按需生成一次类型化字符规则表并调用 `text.hpp`，B2b 不查询本机 Python 或 locale。动态未知规格、自定义格式协议、缺少 locale 的数值 `n` 格式及尚未实现的版本语法保持明确缺口。

单次全局绑定证明扫描闭合程序的写入及循环／函数重入位置。函数读取可证明固定绑定的不可变标量时才保留数值事实；数组仅保留已证明不变的区域形状，不能据此认定内容不变。事实合流区分浮点位模式，不能把正负零合并成一个精确值。前端捕获数值告警的源位置与行文本，后端只打印 IR 内的诊断数据，不重新打开或执行原源码。

帧所有权分析区分被取址的存储与定位它的按值索引：`&array[i + N]` 不意味着 `N` 的地址逃逸。直接取标量地址、引用绑定及未知左值协议仍保留屏障；F4 已记录的地址证据不能被局部推导撤销。M3 的既有循环边界规则再消费这一所有权事实，而不是由后端按函数名删除取模。

F2 用 `buffer.storage=compiler_temporary` 区分值语义所需的编译器物化与源码显式分配。M3 的逐点物化转发只删除该类私有、不逃逸且只被一组生产／消费遍历使用的临时值：两遍必须具有相同整数域和已冻结掩码，目标具有无混叠证明，右值只含同类型普通读取。掩码计算保留在原位置，读取仍留在条件分支内；涉及算术、转换、错位索引、外部调用或未证明分配可消除时不适用。该规则减少临时存储和遍历，不将结构工作量减少宣称为实测加速。

调用域访问前提由 F2 从实际函数定义捕获，M2 形成统一 `access_contract`，M4 校验后交给 B1。B1 只编译固定探针核实目标限定语法，不执行应用；B2 校验物理收据和每个函数合同的摘要，再在类型化参数节点上生成限定。不支持时保留普通定义。普通原生 Fortran 的 `INTENT(IN)` 独立于指向类型，不能据此生成指向 `const` 的元素或省略未知被调过程所需的切片写回；跨语言声明的资格差异由 M2 显式桥接，保留数据类型和机器 ABI。

M2 的数组字面量域只推导源码中已知的有限值，不读取运行时数据。分配身份在一次分析内唯一，view 共用身份，copy 和一元数组运算取得独立身份；未知内容的新分配也保留身份，避免将局部数组写误判为所有全局数组均被改写。别名写入使相关内容事实单调失效，未知基址写入清空内容域。循环先分析可能的回边写入与绑定变化，循环内新分配的首轮事实不带出循环。普通函数使用隔离的内容域，调用摘要区分私有分配写和调用方可达写；这仍是保守证明，不等于完整的跨过程逻辑值身份。

数组序列属于计算域的复合区域。当前 NumPy 2.5.5 标量端点 `linspace` 以已封存导出路径、实现摘要及受支持的标准公开接口合同绑定，展开为端点差、坐标生成、步长判断、缩放、平移和端点写入。下溢分支、空数组及原库警告位置保留，`origin_region` 将生成语句连回源调用站点。当前支持 binary64/default dtype、轴 0/-1、已证不超过 2**53 的整数计数；`retstep` 必须有确定返回布局与源标量类型，其他输入明确拒绝。这不是对所有 NumPy 接口的支持声明。

坐标网格沿同一源证据入口绑定。M2 将 `meshgrid` 的 C-order 展平、单例轴形状和 xy/ij 轴序写为中立 size/reshape/broadcast-copy 操作；稀疏非复制结果保留输入别名，复制结果具有独立存储。密集非复制网格仍需重叠可写 view 及其警告合同。固定序列解包按目标结构顺序下降，绑定、循环回边和异常前缀的写入追踪使用同一叶目标枚举；该枚举不执行 RHS，不按具体程序补连线。

领域规则按子图分工，公共机制仍处理类型、状态、控制、合同和资源依赖。数值区域使用数组／标量合同，图形区域使用上下文、渲染及编码合同，文件和进程区域使用外部效果合同；它们可出现在同一程序中。`array_iota` 是源语言无关的序列叶算子，B1 检查能力，B2 只绑定原生 xtensor 的整数范围和浮点转换，不调用 NumPy，也不手写逐元素计算循环。绘图仍须独立的原生实现，数值叶算子不会补齐图形能力。

规范化按实际消费合同消除区别，不追求在运行时重建所有来源类型。相同 binary64 存储的 Python／NumPy 标量可用同一数值选择、真值和普通格式化操作，M2 只在编译期保留可能的行为集合；不插入转换、类型标签或分派。`min/max` 的多个标量实参先全部按序求值，再通过严格比较选择原有值，保留相等、负零和 NaN 时的首个胜者。若消费操作确实观察来源差异，例如 NumPy 2 的 `repr` 或不同的除零行为，必须另行证明，不能默认为普通浮点。当前仅闭合多个标量参数形式，迭代器、`key/default` 及不同物理表示的动态选择仍有边界。

内建 `int`/`float` 先核实名称绑定，再按源顺序求值实参。整数转换必须证明有限浮点区间向零截断后落在有符号 64 位域内，转换依据记录于 `normalizations`；不能用未经检查的 C++ cast 承接 Python 无界整数。尚未证明的值域、文本解析和自定义转换保持定位缺口。保存的数组 `copy` 方法捕获真实接收者句柄，不随原变量的后续重绑定变化。

整数 `%` 和 `//` 在本层明确 Python 的除数符号与向下取整规则，再生成已有的中立算术和选择操作。非零除数、结果范围及 `INT64_MIN/-1` 边界必须先闭合，不能直接把源操作拼成 C++ 的 `%` 或 `/`。浮点余数和整除尚需独立合同。

文本／布尔／空值原语也消费当前到达的精确标量事实，不只识别字面量节点。由此确定的条件只保留对应分支，操作数求值产生的效果仍在原位置；`exact_primitive_fact` 记录该推导，后续被重新绑定的全局不能沿用旧事实。

清理区把正常结束、返回、循环转移和异常区别处理。B2a 使用类型化 `try/catch/throw` 和局部完成状态，确保清理运行一次；清理中的返回或异常可覆盖原出口，循环内自己的跳转不会误触外层清理。处理器别名退出时清空对应槽，保存到其他变量的异常句柄仍有效。输入与退出也通过中立接口交接，`SystemExit` 不等于直接调用 `std::exit` 跳过清理。显式异常原因与 from None 在错误句柄中保留；自定义上下文管理器、异步协议、任意外部异常动态类型和完整 traceback 仍有明确边界。

M2 `normalization/artifacts.py` 消费已资格化的中立主机操作及精确操作数事实，推导流的有序常量字节，并将逻辑字节值与输入快照连接。它不执行原程序，也不重新解释来源语言。未知调用、可能重叠的句柄、子进程及未展开控制使有关事实失效；循环不展开。证明留在 `plan.json` 引用的分析图内，尚不据此删写入、删编译或生成规范入口。协议遇到首个缺口时，已闭合函数及活跃帧前缀不再丢失，仍不能进入 `READY` 执行包。

C++ 对象的默认特殊成员不等于库函数接口。M2 根据编译器提供的所有者、签名和全部引用，只有确认为结构化构造／析构操作时才省去独立的外部 ABI 声明；对象分配、构造和析构仍保留，不假设它们没有副作用。真实函数调用、取地址、间接目标、已删除成员及不匹配类型均不能应用该规则。此规则位于通用 ABI 正规化，不按 MPI 类型名称豁免检查。

M2 检查闭合直调的实参数量及可变参数下限，不能通过截短参数列表掩盖不匹配。F4 的循环状态图区分初始化、循环头、步进/条件、正常出口和提前出口；自动局部的每次迭代寿命不属于循环携带状态。开放 Python 迭代器显式记录 setup/advance 的共享状态屏障，目标绑定只发生在成功取值路径；上下文和异常区域局部概括，不再清空整函数证据。

F3 区分全局、词法局部、形式参数和引用绑定，并按操作目标端口传播解包、删除、上下文及异常绑定的写入。F4 记录绑定自身及被引用状态的版本。M1 把原状态表、访问和版本关系放入 `state_evidence`，M2 据地址逃逸证据和参数传递方式生成 `state_contract`。当前 M3/M4 消费该归属合同，尚未直接消费源 F4 的版本；通用化简还需 canonical 版本／效果分析。现有规则在进入分支前先失效条件写入，在循环体前先失效初始化、条件、步进及回边的潜在写入。

普通项目类沿同一链路处理。F2 保留类创建规则和每次同名定义的独立链接身份；M1 单列类体及方法候选，不伪造调用边。M2 的 `objects.py` 证明普通方法查找及固定字段布局，把分配、读写和绑定方法接到中立对象引用；字段只保存类型，不从首个实例推定数值。只有定义副作用及所有实际访问已闭合后，才省略未激活的方法体。绑定方法另存接收者运行时槽，跨函数读取不会引用模块初始化的局部暂存。

每个 SCAR 版本固定各层的规则和适用条件。M3 对每个已闭合镜像按同一顺序执行化简，计划记录命中位置与证明。B1 以硬件预算和探针数据作为规则的输入。串行约束将可用 worker 数限制为一，同样执行访存、布局与融合的成本判定。M4 提供等价降级的合同。未闭合的源协议使执行包成为 `INCOMPLETE`；逻辑算子已闭合而缺少目标实现时，由 B1 拒绝，不能混淆这两类状态。前端资源图及其来源随执行 IR 交付，后端另核对部署时实际资源。

M2 的 `graphics.py` 将已核实 Matplotlib 3.11.2 的公共接口表达为图形上下文、列系列曲线、网格状态和保存操作。上下文导入保留初始化与命名空间条件，不能无效果化；曲线在 `plot` 调用时取得数组快照，保存读取当时的图形状态、配置、文件系统和时钟。原生渲染、编码及初始化的等价实现仍未注册，逻辑 IR 的 `READY` 不代表可以交付该程序。

## 下一步：规范交付入口（尚未实现）

源程序入口是分析根，不是生成程序的接口约束。中端将按依赖把配置、构建及运行操作分阶段：只决定代码／编译配置的已确定值进入构建计划，本次数据所需的准备、计算、科学日志和结果文件仍进入执行 IR。构建工具、目标及消费关系来自已绑定的构建子图，不按源语言或函数名猜测。构建日志迁到构建产物，不伪造为运行输出；这是用户授权的交付接口规范化，不能作为数值优化收益。

该工作归 M2 的图关系规范化和 M3 的子图化简：先依据值及状态版本、读写和控制关系证明子图结果，再做常量传播、部分求值、阶段前移和冗余中间表示消除；不能按“Python 生成 Makefile”之类源代码模式定义规则。后端只消费封存后的构建／入口合同及执行 IR，生成 C++20、标准构建规则和交付清单，不再解释 Python 或原 Makefile。当前 `build.bindings` 已连接编译产物来源；从原控制器中提取构建阶段及生成规范入口仍是待实现变换。编译配置去重保留源编译器驱动、可用的工具文件摘要及其捕获时点；它们与实际分析器身份分别记录，不能视为历史编译环境的完整重建。

AMSS 当前已保存的官方驱动图含宏文件生成、复制、进程启动／流／等待等结构，真实构建子图也已捕获；默认输入下能静态推导初始输入文件及两个宏文件的字节，并分别表示编译输入快照和历史版本义务；完整 ABE 的生成物、消费者版本及规范入口变换仍待闭合。结构覆盖和通用 co-input 机制不代表该完整工作流已经闭合。

当前完整驱动仍未闭合，ABE/TwoPuncture 原生子镜像可独立编译。异构聚合值、受限复数和一维 FFT 已有局部合同与验证，不能再将它们统称为未实现；导入命名空间的原生供应、实际可达的其余数值/图形接口、生成文件到历史构建输入的版本证明及规范入口仍待完成。具体首个缺口、耗时和验证版本统一记录在 `artifacts/current/verification.json`，不在本设计文档维护另一份运行进度。

文本数组默认读取已为 NumPy 2.5.5 的具名 UTF-8 借用流提供原生接口，保留游标、空输入警告、转换错误及解码错误。B1 校验解析配置、流来源与捕获的告警位置；B2 从类型化目标树调用可选 `array_io.hpp`，普通数组计算不依赖该文件。读取结果携带秩集合 `{0,1,2}`，reshape 输出携带已确定秩，动态轴长保留为运行时值。文件名输入另表示 `array_source_open`：其压缩文件候选搜索、URL 和缓存效果尚未绑定，B1 在调度和代码生成前拒绝；不能把它直接替换成普通 open。此局部通路通过独立三阶段、移除上游产物后的输出对照，不等于完整 AMSS 交付通过。

两条文件事实传播规则已修复：稳定全局来源沿局部变量复制保留，失效与合流仍按作用域和写入处理；返回已关闭流不等于返回可修改文件的能力。来源表仅属于当前激活，不取消原有 epoch 和外部效果守卫。随后补不可变异构聚合的跨调用合同：M2 在源构造点按顺序捕获元素并生成一次 `product_make`，以 `product_get` 读取静态字段，不能在每次返回或传参时重造对象。常量池与动态构造的身份依据分开；身份来源不明时禁止批准可观察身份的操作。M4 封存字段的逻辑类型和别名摘要，数组的 fresh-per-call 来源按激活实例化，不能跨帧复制分析器分配编号。B2 通过类型化目标树生成共享的只读乘积对象，数组成员保留原存储别名。仅在 M3 证明对象身份、逃逸和生存期不被观察后，才允许拆字段或改为按值传递；不能默认把 Python tuple 按值复制。这一聚合合同尚未实现。

统一的是工程布局、参数声明、依赖清单和构建／运行分离；单进程 CLI、MPI rank 入口、原生控制器以及可调用库保持各自的角色。公共入口可调用同一 IR 生成的内部计算阶段，不要求单个进程同时承担全部角色。现有 CMake/MPI/OpenMP 机制继续使用，CLI 与任务执行器按实际需要引入，不叠加多套调度线程池。

## 后端

| 层 | 输入 | 处理与输出 | 实现 |
| --- | --- | --- | --- |
| B1 物理规划 | `exec-ir.json` | 资源约束、校准、按合法布局的成本与选择，封存 `physical-plan.json`、`scheduled-ir.json` 及函数成员 | `planning/` |
| B2a 目标降级 | `scheduled-ir.json` | 类型化 C++ 目标树，封存 `target-ir.json` 及翻译单元成员 | `cpp20/target.py`、`lowering.py` 及同层领域模块 |
| B2b 打印封装 | `target-ir.json` | 从目标树打印声明、类型、表达式和语句，LLVM 格式化，封存工程及 `cpp20.json` | `cpp20/project.py`、`printer.py`；共享目标模型与纯收据校验 |
| B3 构建 | `cpp20.json` | 验证工程成员，CMake 构建并安装，输出 `build.json` 和可执行文件 | `build.py` |

局部数值缓冲区由 M4 标记 `private_scratch`。适用条件包括标量下标读写、作用域内独立绑定以及可见地址和分配效果检查。B1 读取目标 CPU 的 L1 数据缓存线和内存页大小，每个合格缓冲区最多使用一条缓存线的内联容量，每函数的内联数据预算为一页。B2 在实际长度超过容量时调用 `new[]`，使用原元素类型及初始化方式。缺少证明或目标数据时，物理计划沿用堆分配。

B2a 的目标树使用 `Type`、`Expr`、`Stmt`、`Decl`、`Attribute` 和 `Unit` 记录。类型、控制流和函数体都通过这些节点构造。打印器只依赖目标树模型和 Python 标准库。原始应用源码及其语法不进入后端。固定 C++ 支持代码是独立的 `runtime.hpp`；硬件探针是独立的 `calibration.cpp`，均遵循 LLVM 格式并随包安装。

目标包同时封存所需 SDK 头文件的字节收据，打印层直接消费该固定版本；安装中编译器的 SDK 更新不会改变已封存目标。传统仅含 SDK 摘要的包仍要求精确匹配，不能用新版头文件冒充旧版本。文本输出的值类型、拼写格式、UTF-8 编码和求值顺序均由统一 IR 指定，后端只实现这些合同。

原生 xtensor/xtl 也沿此合同交接：B2a 核对 B1 选择的安装收据及每个依赖头文件，并封入目标包。B2b 从收据恢复工程内的 `vendor/xtensor-cpu`，CMake 不再查询环境重新选择数组 SDK；B3 不需要原安装目录。第三方头文件保持其已核验字节，CI 的 LLVM 格式检查仅针对 SCAR 和生成的应用代码。旧目标包若仅记录库名而没有封存身份，必须从有精确收据的调度包重新降级。数组元素已区分 f64 与 c128；一维 c128 的原长度、ortho FFT 使用固定 PocketFFT 提供，头文件与许可证一并封存。NumPy 默认浮点警告是独立效果；模块惰性绑定、枚举及绘图供应不由 FFT 库代替。

目标模型拥有统一语法合同，按位置检查节点种类、必需字段、操作数数量、操作符及声明作用域。B2a 封存前检查，B2b 打印入口再次检查自身输入；每个消费步骤只遍历验证一次，不依赖摘要替代语法检查。完整 C++ 类型检查由 B3 编译器承担。

共享对象布局在 B2a 通过 `shared_ptr` 保留身份，通过可选字段区分未绑定和已写入空值；缺失读取按 IR 中的类别和消息抛出异常。实例传参和返回复制引用，数组字段复制共享视图句柄。该布局与原 C/C++ 值记录分别验证，不改变原 ABI。当前仅承接反射闭合、无继承或自定义查找协议的固定类型字段；描述符、元类、字段换型及循环对象引用仍需独立合同。

B2b 的 `print_target(..., jobs=4)` 并行格式化独立文件，最多四个外部进程，并按亲和性和 cgroup 配额收缩。文件按大小派发，封存顺序固定；失败时等待在途写入结束后才清理，项目整体成功后才发布。此并行度属于编译工具自身，与生成程序的线程调度分别配置。

B1 决定工作线程和存储方案，B2a 实现已选择的机制。B2a 不重新证明循环的形状、别名或控制流，B2b 不规划调度，B3 不读取执行 IR。公开层接口分别为 `schedule_ir`、`lower_scheduled`、`print_target` 和 `build`。各自接收上一层完整文件包，可移动到新目录独立运行。

B1 的 `toolchain.py` 单独资格化目标编译器：固定探针只编译／链接，不运行应用；跨函数镜像在 GNU LTO 资格通过后封存编译策略和预算，不支持或显式关闭时保持普通编译。B2a 核对策略与调度 IR 的摘要绑定，转为目标树包的 `build_options`；B2b 仅消费此字段生成 CMake。工程先并行编译所有镜像的目标文件，再逐个链接，将每次 LTO 的并发限制在封存预算与部署上限之内。B3 只消费工程清单。此策略保持原浮点选项，不代表已有实测收益。

B1 先合并显式 `operator_requirements` 与节点的 `operator_family`，再核对族、操作、数据类型及实际 SDK。只有资格通过才启动成本校准和调度。缺失绑定会封存 `INCOMPLETE` 的物理计划和调度包，给出 `missing_operator_binding`；编排返回该结果，不导入 B2/B3。多镜像分别记录资格，任何镜像失败都不能将整包标成可交付。

B1 在原有诊断代码之外，以 `qualification.stage/rule/evidence` 区分源语义合同、实现配置、目标平台及外部效果问题。证据只保留有界样例及省略数；真实 SDK、ABI 和启动器资格失败保留原原因，不按错误文本猜类别。接口可绑定与子进程／导入效果已闭合分别记账，前者通过不能覆盖后者。

B1 同时扫描实际执行字段中的 `process_request`；即使 IR 遗漏族标签或需求表，也报告 `missing_process_target_binding`，封存请求 ID、调用点及义务。该镜像不进行物理供应者探测、CPU 成本调度或 C++ 生成；已绑定的 `process_spawn` 保持原资格路径。

进程资格另与外层 IR bundle 核对，B1 为目标封存真实子 IR 摘要及输出名，丢弃输入中自带的物理绑定。B2 仅据此生成同一发布目录内的 `posix_spawn` 调用，保留原 argv[0] 和参数边界；部署合同要求运行期间发布代不变。当前支持继承输入、单 stdout 管道、继承或合并 stderr、共享流和重复显式等待；任意 shell、未资格化工具、运行时构建及全程序进程调度尚未闭合。固定 rank 的单机 MPI 启动由 `planning/mpi/launcher.py` 对照已封存子镜像 SDK 资格化，保留原 argv、工作目录和简单 shell；shell 仍通过已核验的 `/bin/sh` 执行，不能以返回码转换模拟。运行前检查启动器及 shell 字节，原 `./worker` 必须是同一发布代的文件或字节相同副本，否则拒绝，不能回退原版二进制。当前启动器资格适配已登记的 Debian/Ubuntu Open MPI 安装，其他供应需独立适配。原生句柄析构不隐式阻塞或终止子进程，未退出 PID 在后续启动时机会性回收，需要确定回收时点时须显式等待。

B1 按实际整数/浮点类型、商余共享、访存和控制成本定价，分别比较线性与坐标遍历。校准值为观测，合成时长为估计。未校准操作保留明确的串行回退。当前模型仍未覆盖完整 MPI 通信关键路径、缓存行为和全程序存储调度，局部选择不能作为全局最优的证明。

B1 的 `movement.py` 独立消费 M4 资源流，给逐次复制保留物化、调用线程域、符号字节量及时间约束。符合条件的主机连续复制与循环共用一份校准程序：8 MiB 的库 `memcpy` 测三次，按 payload 字节归一，形成有明确适用范围的复制分量代理。分配、页错误、缓存状态和实际放置未计入时，总 duration 保留未估；广播、重叠未证的 memmove、文件及设备传输不套该系数。固定串行策略和仅文件复制不触发该探针。当前保持原执行顺序，尚未自动前取、重叠传输或完成全图时间调度。

F5 保存可见数据挂载的内核 ID、文件系统根、挂载点、只读状态及采集命名空间，保留 tmpfs 与磁盘/网络文件系统的区别。输入挂载通过层级解析，无法证明可见性的叠挂保持未决；仅查询输入挂载容量，避免遍历触发网络文件系统等待。挂载与可证块设备连接，不能仅按路径名称判定 SSD/NVMe。B1 仍须取得执行环境的位置事实，不能沿用编译采集目录的挂载作为运行位置。

F5 分别记录 sysfs 可见的逻辑 CPU、在线掩码和进程亲和性。只将进程亲和性中的 CPU 通过 `CPU_POOL_MEMBER` 连入池，结合祖先 cgroup 限额计算预算。缩小采集进程的亲和性仍保留物理核、共享缓存和 NUMA 拓扑。图保留分数容量上界和保守 worker 预算，二者不能等同于最佳线程数。B1 进一步施加 OpenMP 和调用方上限；F0 建图任务、B2b 格式化和 B3 构建分别按同一事实限制自身任务数。各消费者在执行时重新读取，避免沿用前一阶段过期的主机约束。

## 持续验收与当前边界

CI 从安装后的 wheel 验证三阶段及层间隔离，检查 Black、LLVM 格式和零告警编译。语言层测试断开源码与解析工具，中端测试禁止导入其他处理层，后端测试逐层搬移产物并禁止前层实现。实际输出对照用于验证整个通路，局部测试和接口检查各自保留其范围。

真实 CXSparse、AMSS 的 TwoPuncture 初值计算和 16-rank ABE 演化均有输出对照。ABE 单步的私有临时缓冲区经过 M4 访问证明、B1 存储预算和 B2 布局后，相对上游实测 1.139×。性能证据绑定可执行文件、输入和 rank 放置。整套驱动另行验收。测量条件和结果见 [README](../README.md)。

M4 在未完成的镜像 IR 中封存上游报告的原因、源码位置及证据，执行函数表为空。B1 仅读取 IR，即可把原因连同镜像身份写入物理计划，独立资格化其余镜像。整包为 `INCOMPLETE` 时，编排止于 B1。可单独将已就绪且依赖齐备的求解器调度包交给 B2，生成工程再由 B3 构建。

完整 AMSS 图中的 SciPy 冷导入及懒加载仍带未闭合合同，来源链、模块身份及导出候选已封存；这不等于其数值算子已有原生绑定。效果失效分析还会暴露更早的数组内容和数值范围证明缺口，不能用首个诊断的位置证明后续路径已经验证。绘图对象、二进制数组读取、FFT/窗口及插值合同仍未闭合。绘图操作也无原生供应绑定，不能把中端认识 `plot/savefig` 宣称为可交付。C++ 字节输入流已连接到条件缓冲版本，复制的目标分支及启动前文件环境也已封存；跨镜像的参数状态、实际消费版本与时序连接仍待完成。

多程序镜像沿用每层现有处理器：F0 给出去重单元及镜像归属，M1 在每个镜像内绑定，M2—M4 分别正规化、化简和封存；B1—B2a 分别消费各镜像的独立 IR，B2b 生成多个 C++20 目标，B3 一次构建、检查并发布全部可执行文件。总包通过相对收据组织子包，不使用跨镜像全局符号表。入口及普通单镜像调用保持原接口。

这条镜像链路尚不等于官方 Python 驱动闭环。后续需要把进程协议绑定到明确目标及实例，接通两条独立文件链和退出/日志协议，再完成运行时构建与后处理的原生接口。无证据时不能用执行完毕代替文件版本证明，也不能把每镜像成本相加当作全工作流关键路径。

构建输入首先经过独立的发现子流水线：锁定 Bear 3 原始事件字节 → `builds/facts.py` 解码命令并快照命名文件 → `builds/normalize.py` 离线生成编译配置、镜像归属与构建依赖子图。它为 F0 解析请求补全单元任务；构建格式规范化不等于 F2 的程序操作规范化。所有单元随后严格沿同一 F1 语言事实 → F2 中立操作 → F3 构图 → F4 状态分析进入 F5 封存。M1 校验构建子图收据和诊断，后端只读取统一执行 IR，不重放原构建命令。Bear、readelf 仅在前端使用。

可选进程证据沿同一层级交接：`languages/python/process_capture.py` 独立运行，仅在启动审计和指定构造函数的局部返回处记录有限事件；`builds/process_tree.py` 只解码进程系统调用日志，`builds/facts.py` 合并实际 PID 与工具包装映射，F2 转交事实；`artifacts/processes.py` 在 F5 连接源操作端口，不回读源码、不执行采集。进程事件不授权删除构建或文件操作；消费者版本及阶段前移仍由中端另证。局部返回机制参见 [CPython monitoring](https://docs.python.org/3/library/sys.monitoring.html)，包装 PID 的区别来自 [Bear 3.1.3](https://github.com/rizsotto/Bear/blob/3.1.3/source/intercept/source/report/wrapper/EventReporter.cc)。

库证据分为显式链接需求、现有 ELF 的 `DT_NEEDED` 和运行时实际加载；前两者不能证明第三者，也不能证明该库已经是最快实现。文件和工具摘要说明采集时内容，不假称历史构建时内容；未记录的旧对象、未闭合的生成文件和命令依赖必须保留边界。Bear 原始环境只提取编译、库搜索及并行控制白名单，完整环境不进入图包。不能将 `make -n` 当成绝不执行的静态解析器：GNU Make 的递归调用与部分展开仍会执行。[Bear](https://github.com/rizsotto/Bear/tree/3.1.3) · [GNU Make](https://www.gnu.org/software/make/manual/html_node/Instead-of-Execution.html)

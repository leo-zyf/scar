# 分层与阶段交接

每层操作上一层的结构化产物。公共 `scar/contract.py` 定义版本、序列化、资源记录、内容摘要及包内文件收据。`scar/cli.py` 延迟导入被选择的阶段。

| 层 | 输入 | 操作 | 产物和实现 |
| --- | --- | --- | --- |
| F0 输入锁定 | 编译单元清单、语言、方言、宏、头文件锁 | 校验源码及每种编译配置 | 单元任务和内容版本，`frontend/__init__.py` |
| F1 解析与绑定 | 单元任务 | Python AST、Clang 类型化声明、fparser 语法和 GNU 语义证据 | 结构化过程、作用域、类型和调用符号，`python.py`、`c_family.py`、`fortran.py` |
| F2 操作正规化 | 语言结构及编译事实 | 表达式、循环、数组索引、状态和协议正规化 | 同一操作词汇，`fortran_ops.py`、`cxx_objects.py`、`cxx_library.py` 和对应语言适配器 |
| F3 建图 | 正规化过程 | 操作端口编号、控制区域、状态访问和循环携带版本 | 单元子图，`graph.py`、`state_flow.py` |
| F4 资源与观测 | Linux 系统信息、可选受限入口 | CPU/物理核/NUMA/DRAM/存储/设备拓扑及形状证据 | `graph.json` 根索引和 `units/` 子图，`hardware.py`、`observation.py` |
| M1 连接和闭包 | 完整图包 | 入口可达性、跨单元 ABI、对象方法、回调目标和记录布局 | 封闭类型化模块及定位问题，`middle/link.py` |
| M2 合法图改写 | 已封闭模块 | 精确常量折叠、重复迭代边界共享、满足无别名约束的循环融合选择 | 逻辑操作、证明和参考执行路径，`middle/rewrites.py` |
| M3 执行 IR 封存 | 逻辑模块和改写记录 | 独立封存函数和类型、效果、外部接口 | `plan.json`、`exec-ir.json`、`functions/`，`middle/__init__.py` |
| B1 物理规划 | 执行 IR、当前可用 CPU、校准 | 测量线程、带宽和运算成本，计算随规模变化的线程调度 | `physical-plan.json`，`backend/cpu.py` |
| B2 目标降级 | 选定的执行 IR | 类型、控制流、对象和外部算子接口映射为 C++20 | 共享头文件和分片源文件，`emission.py`、`object_model.py`、`libraries.py` |
| B3 工程构建 | 生成源码和目标库 | CMake 配置、并行编译和安装 | `project/`、可执行文件、日志和 `result.json`，`project.py`、`backend/__init__.py` |

F1/F2 使用语言工具读取源语言事实。所有可执行内容在 F3 转为 SCAR 操作图。中端只读取图产物，后端只读取执行 IR 产物。原始源位置和图摘要服务于追溯；后端运行依靠执行 IR 中的完整操作及声明的目标库 ABI。

中端决定依赖、恒等改写和合法并行空间。后端负责目标机器上的线程数、阈值、算子绑定、工程和编译选项。当前成本模型已实现逐元素区域的启动、内存和算术估算；跨 MPI 进程、NUMA 迁移和全流水全局调度仍需扩展。CPU 探针以独立 C++ 程序运行，最终性能由干净的原版/恒等生成版/逻辑改写版/物理调度版比较。

目标库调用显式携带 provider、类型和 ABI。C++ 标准库、C 标准库、MPI、GNU I/O 分别在后端绑定到已声明的接口。当前 GNU I/O 还需要前端提取运行库布局并由后端作大小和偏移校验。增加语言适配器应输出同一图格式，增加设备后端应消费同一执行 IR；两者分别在自己的阶段扩展。

最终 AMSS 验收覆盖官方驱动到后处理的 5M CPU 用例和科学输出。已通过的单过程、CXSparse 和阶段隔离检查各自记录范围，完整 AMSS 验收记录须包含生成版运行结果后才可标记通过。
